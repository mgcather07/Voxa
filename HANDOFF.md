## What Voxa is

**Voxa** is an internal **Call Telemetry** web app for Cisco Unified
Communications Manager (CUCM). Today it is a **read-only phone inventory &
refresh planner**: it pulls a live phone inventory from CUCM and turns it into
a refresh plan — what phones exist, what each maps to, which switch port each
one is on, and what the swap does to the PoE budget per closet. It **never
writes to CUCM** — every call is a read.

Call telemetry (CDR/CMR ingest — call volume/quality per device) is on the
roadmap; the inventory/refresh tooling is the foundation that ships first.

## Get it running on a fresh machine (e.g. the Mac Mini)

```bash
# 1. Clone
git clone https://github.com/mgcather07/Voxa.git
cd Voxa

# 2. Create the virtualenv and install dependencies
make install                 # = python3 -m venv .venv + pip install -r requirements.txt
source .venv/bin/activate

# 3. Create the local testing config (SQLite + mock data + auth off)
cp .env.local.example .env

# 4. Seed 600 fake phones (no CUCM needed)
python scripts/mock_data.py 600 --wipe     # or: make mock

# 5. Run it
make dev                     # http://localhost:8000
```

That's the whole loop. `.env`, `local.db`, and `.venv/` are **gitignored** (the
first holds secrets, the other two are rebuildable), so they don't travel with
the repo — steps 2–4 recreate them. Everything else is in git.

Login is **off** locally (`AUTH_DISABLED=true`). To test with login on, set it
to `false` in `.env`, then `python scripts/manage.py create-user admin --admin`.

## Deployment plan (decisions so far — nothing built yet)

Target: a **Linux VM on the company vSphere estate**, behind nginx with TLS.

- **VM provisioning:** clone from the company's golden Linux template (patched,
  monitored, backed up by IT tooling). Building a custom **OVA** is *not* worth
  it for a single internal instance — OVA only pays off for mass distribution.
- **Running the app on the VM — two supported paths, already in the repo:**
  - **Docker Compose** ([docker-compose.prod.yml](docker-compose.prod.yml)):
    bundles Postgres + app + nginx; clean upgrades. Preferred **if Docker is
    approved on the server estate.**
  - **systemd native** ([deploy/voxa.service](deploy/voxa.service)): fallback if
    containers aren't allowed; install Python/Postgres/nginx on the host.
  - **The one open question that decides this:** *Is Docker allowed on server
    VMs?* — ask infra/security.
- **Pre-deploy dry run:** before touching the VM, run the prod stack once on a
  laptop to shake out Postgres-vs-SQLite, nginx, and TLS differences. Docker
  Desktop needs a paid license at larger orgs; **Colima** (`brew install colima
  docker docker-compose`) is a free drop-in. Not needed for normal app testing —
  only for the deploy rehearsal.
- Full VM sizing, firewall, TLS, backup, and upgrade steps: [docs/DEPLOY.md](docs/DEPLOY.md).

## Gotchas worth remembering

- **`make mock` / `make dev` need the venv activated** (they call bare
  `python`/`uvicorn`). Run `source .venv/bin/activate` first.
- **AXL only runs on the CUCM publisher.** Pointing at a subscriber looks like a
  permissions error.
- **Never let the app write to CUCM** — read-only is why it's approved against
  production. See CLAUDE.md.
